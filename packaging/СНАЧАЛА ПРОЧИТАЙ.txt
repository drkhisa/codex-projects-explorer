CODEX PROJECTS EXPLORER 0.7.2 — ОБЩИЙ КОМПЛЕКТ

ИСПРАВЛЕНИЕ 0.7.2
После загрузки каталога модель и глубина размышлений (effort) снова доступны для выбора. Во время ответа можно выбрать настройки следующего запроса очереди; это не меняет модель уже выполняющегося хода. Уточнение через Ctrl+Enter / turn/steer продолжает текущий ход без замены модели. Пока каталог пуст или запрос ожидает подтверждения приёма, оба списка недоступны.
В настоящем изолированном VS Code 1.145.2 подтверждены доступность обоих списков после загрузки и во время ответа, смена модели с gpt-6.1-sol на gpt-6-astra через событие change и обновление допустимых effort. UI/warm отчёты pass:true; очередь, clipboard, handoff, кэш и компактное поле также прошли.

УСТАНОВКА
Распакуйте архив целиком в отдельную папку. Windows: прочитайте
Windows/Инструкция-Windows.txt, запустите Установить.cmd. Mac: прочитайте
Mac/Инструкция-Mac.txt, используйте Установить.command либо установите
codex-projects-explorer-0.7.2.vsix через Extensions: Install from VSIX.
После обновления выполните Developer: Reload Window. Установщики ставят только
расширение VS Code. В каждой папке есть browser-bridge и его отдельный ZIP.
Компонент браузера — 0.7.2; его протокол не изменился с 0.6.0. При переходе
с 0.5.x обновите компонент и все вкладки ChatGPT. Установка в браузер ручная,
описана в browser-bridge/ПРОЧИТАЙ.txt. Source code ZIP GitHub не установщик.

КЛАВИШИ (С 0.7.1)
Enter всегда ставит запрос в очередь; в простое очередь запускает его сразу.
Ctrl+Enter / «Уточнить сейчас» уточняет работающий turn через turn/steer
с expectedTurnId, в простое Ctrl+Enter отправляет новый запрос. Shift+Enter —
новая строка. Удержание Enter не отправляет повтор. Fn+Enter работает как
Ctrl+Enter только если клавиатура/ОС передают Fn в DOM; скрытый Fn определить
нельзя, без модификатора это обычный Enter. Физический Fn не проверялся.

WRITER-БЛОКИРОВКА МЕЖДУ ПРОЦЕССАМИ НЕ ИСПРАВЛЕНА
Другой клиент, включая Desktop, может удерживать writer даже после ответа.
Освобождается только сервер, запущенный расширением. Для продолжения исходного
чата требуется освобождение владельцем. Принудительного перехвата и скрытого
fork нет; пользовательские чаты/config автоматически не меняются.

«В очередь» добавляет отдельный следующий запрос. Очередь видна, до 10 запросов,
элемент можно убрать. Запросы идут последовательно после завершения предыдущего
хода и освобождения writer. Права проекта заново берутся перед каждой отправкой.
Stop, ошибка и разрыв связи приостанавливают очередь; «Продолжить очередь»
нажимается явно. Неизвестный исход не переотправляется: проверьте историю
и удалите неопределённый элемент перед продолжением. Очередь хранится только
пока панель открыта; закрытие панели или перезапуск её не сохраняет.

ЛЮБЫЕ ФАЙЛЫ, ДО 10 ВЛОЖЕНИЙ
Picker не фильтрует расширения. До 10 элементов на сообщение, включая папки,
скиллы и плагины; любой файл до 50 МиБ. Одна вставка из буфера — суммарно до
50 МиБ. Ctrl+C копирует, Ctrl+V вставляет в поле Codex, в том числе во время
ответа. Затем выберите отправку, уточнение или очередь. Обычный текст вставляется
как раньше. Поддерживаемые изображения до 10 МиБ идут как native image input;
известный текст до 256 КиБ — содержимым в контекст. Крупные изображения 10–50 МиБ,
крупный текст и бинарные/остальные файлы передаются локальным путём для
инструментов, без автозапуска и декодирования binary как UTF-8. Прикрепление
пути не гарантирует наличие инструмента чтения формата. Копии вставленных
вложений остаются в локальном хранилище расширения для истории.

СОХРАНЁННЫЕ ВОЗМОЖНОСТИ
Компактное поле 76 px с ручным «Развернуть / Свернуть», кэш метаданных с показом
дерева до ответа сервера и фоновой сверкой, освобождение idle writer для другого
клиента, индикаторы активности на чатах/родителях, проекты и текстовая отправка
ChatGPT через браузер. Чужой работающий клиент не прерывается. Кэш не отменяет
RPC и не является облачной синхронизацией. Онлайн-вложения, выбор модели из
VS Code, архив/удаление ChatGPT и полнота аккаунта не реализованы/не гарантированы.
При неизвестном исходе онлайн-отправки сначала проверьте исходный чат.

«Архив Codex» показывает архивные чаты по исходным проектам. Для отправки
сначала восстановите чат. Удаление навсегда требует именованного модального
подтверждения и удаляет также дочерние истории; файлы проекта остаются.
Работающий чат удалить нельзя, архив/состояние проверяются повторно.
Отмена или ошибка API не запускает ручного удаления истории.

ПЕРЕДАЧА ЧЕРНОВИКА В ИСХОДНЫЙ ЧАТ DESKTOP

очереди — его «В Codex». Открывается тот же ID, без fork и автоотправки.
Если полный URI длиннее 1800 символов, по этому нажатию весь draft копируется
в системный буфер, чат открывается без query; вставьте Ctrl+V и отправьте.
Вложения идут текстом как локальные пути/контекст, не карточками Desktop.
Draft/вложения/очередь в VS Code сохраняются. ПОСЛЕ ОТПРАВКИ В DESKTOP УДАЛИТЕ
ЭЛЕМЕНТ ОЧЕРЕДИ ВРУЧНУЮ, чтобы не отправить его повторно. Чужой процесс не
останавливается, lock не снимается. Установленный parser поддерживает
prefillPrompt; реальный Desktop с пользовательской историей не открывался.
Настоящий VS Code с двумя native App Server и stub Desktop opener проверил
кнопки и сохранение данных; OS openExternal/clipboard проверены Node-стабами.

ДЛИННАЯ ИСТОРИЯ И АКТИВНОСТЬ
История через современный App Server открывается страницей до 20 последних ходов в хронологическом порядке. «Ранние сообщения» заменяет текущую страницу предыдущей, «К последним сообщениям» возвращает к актуальной; черновик сохраняется. Переходы истории недоступны во время активного хода и отрисовки. Отрисовка уступает интерфейсу управление каждые 40 элементов, без пересчёта прокрутки после каждого исторического tool. Старый API thread/read и локальный JSONL-fallback по-прежнему загружают историю целиком: ускорение по страницам для них не гарантируется.

Когда lifecycle-событие начала хода ушло за последний 1 МиБ журнала, определение активности ищет последнее lifecycle-событие назад блоками по 256 КиБ с ограниченным буфером. Отдельные JSONL-записи крупнее 1 МиБ при таком поиске пропускаются; oversized event_msg или нечитаемое начало такой записи оставляет статус неподтверждённым, чтобы не восстановить уже завершённый ход как активный. Попытка обратного поиска кэшируется, неизменённый unknown-журнал не перечитывается целиком при каждом опросе. Повторные проверки читают дописанные байты; порог свежести остаётся 2 минуты. Статус notLoaded чужого App Server и status последнего сохранённого хода не доказывают простой другого клиента; долгий ход без свежих событий по-прежнему может получить «Статус не подтверждён».
