# Codex Projects Explorer 0.7.1

Проекты и чаты Codex в VS Code: центральный диалог, файлы справа, управление переписками и выбор скиллов/плагинов.

Доступны уточнение работающего Codex через «Уточнить сейчас», видимая очередь следующих запросов и любые форматы файлов. Лимит сообщения — 10 вложений, включая папки и скиллы; каждый файл до 50 МиБ. Очередь существует только в открытой панели, без сохранения между перезапусками.

PATCH 0.7.1 исправляет клавиши и добавляет передачу черновика в исходный чат Desktop: Enter — очередь, Ctrl+Enter — уточнение текущего ответа или отправка в простое, Shift+Enter — новая строка. Fn работает только при переданном DOM-модификаторе; физический Fn не проверялся. Межпроцессный конфликт writer этим PATCH не исправляется.

## Установка

**Windows:** откройте VS Code, распакуйте `Codex-Projects-All-0.7.1.zip` целиком, откройте папку Windows, дважды нажмите **Установить.cmd**, затем **Установить** в графическом окне. После завершения перезапустите VS Code. Установщик ищет работающий редактор, App Paths, стандартные расположения и PATH. Если нужно, выберите `Code.exe` из папки редактора или `bin/code.cmd`. Права администратора и Node.js не нужны. Это сценарий с графическим окном, не подписанный EXE; системная политика PowerShell не меняется.

**Mac / установка вручную:** используйте `codex-projects-explorer-0.7.1.vsix`. В VS Code нажмите **Cmd+Shift+P → Extensions: Install from VSIX…**, выберите файл и перезагрузите окно. Универсальный VSIX подходит для macOS Intel/Apple Silicon, Windows и Linux.

Требуется VS Code 1.95+ и установленный совместимый Codex. Официальное расширение OpenAI оставьте: его бинарный файл используется по умолчанию. Можно указать отдельный CLI. Используется авторизация выбранного `CODEX_HOME`; отдельный API-ключ расширение не запрашивает. Возможности project/list, project/create и плагинов зависят от версии Codex. Устаревший сервер выдаёт понятную ошибку; локальный ярлык вместо настоящего проекта при создании не подставляется.

После обновления выполните **Developer: Reload Window**. Браузерный протокол не изменился с 0.6.0; компонент в комплекте имеет версию 0.7.1. При переходе с 0.5.x обновите компонент и перезагрузите все вкладки ChatGPT. Установщик VSIX не обновляет браузерное дополнение автоматически.

## Быстрый запуск и кэш

После запуска сразу показывается сохранённое дерево, затем выполняется фоновая сверка каталога. Кэш в профиле VS Code содержит только разрешённые метаданные, включая названия и короткие preview, без turns, авторизации и старого runtime-статуса. При первом чтении серверу разрешена сверка базы, повторные запросы используют её состояние.

Для локальных JSONL повторно используются summaries с неизменными size/mtime/ctime; новые и изменённые файлы читаются, удалённые исчезают, индекс названий применяется отдельно. Переключение архива не требует перечитывать неизменённые summaries. Лёгкие запросы каталога остаются нужны для новых записей, удаления и архива — кэш не отменяет RPC и не является синхронизацией облачного аккаунта.

## Порядок внутри проекта

Закреплённые чаты показаны первыми, затем категории, затем остальные чаты без категории. Скиллы находятся после чатов. Закреплённый чат из категории показывается один раз над категориями; его назначение сохраняется, при откреплении он возвращается в категорию. Порядок закрепов сохраняется отдельно и меняется перетаскиванием или через меню.

## Новый чат

В дереве под переключателем раздела всегда видна строка **＋ Новый чат**. Нажмите её и выберите **Новый чат вне проекта** либо нужный проект. У каждой строки проекта есть кнопка **＋** при наведении — сразу создаёт чат в этом проекте. В заголовке панели также есть кнопка нового чата. Контекстное меню проекта сохранено.

Вне проекта создаётся настоящий `thread/start` с `projectId: null`, без фиктивного проекта. Для выполнения команд используется отдельная служебная рабочая папка. Такой чат показывается плоско в **Отдельных чатах**, без папки new-chat в дереве. Принадлежность к отдельным чатам сохраняется после перезапуска. В разделе ChatGPT кнопка нового чата открывает исходный ChatGPT: локальная сессия Codex за онлайн-чат не выдаётся.

После первого принятого текстового сообщения его сокращённый текст становится подписью дерева и вкладки; отклонённая отправка её не меняет. Заданное имя имеет приоритет, следующие сообщения не заменяют исходную подпись. Генерация названия моделью не добавлялась.

## Онлайн ChatGPT — браузерное расширение

В VS Code: **Ctrl+Shift+P** (Mac: **Cmd+Shift+P**) → **Codex Projects: Подключить онлайн ChatGPT**. Затем **Подключить браузер**. С установленным компонентом браузер свяжется автоматически и откроет ChatGPT — копирование кодов не нужно.

Общий архив `Codex-Projects-All-0.7.1.zip` содержит папки Windows и Mac, две текстовые инструкции, браузерную папку и отдельный ZIP в каждой папке платформы. Длинный блок установки удалён из центрального окна. Установщик VS Code-расширения не выдаётся за установщик браузерного компонента.

**Установка браузерного компонента двойным кликом пока не реализована.** Для обычной внешней установки в Chrome на Windows/macOS сначала требуется публикация в Chrome Web Store; Edge также предусматривает установку через магазин. У расширения нет опубликованной карточки и ID. Добавление локального ZIP/CRX к установщику это ограничение не снимает. В комплект включён исходный компонент; ручной способ описан в его ПРОЧИТАЙ.txt. Системные политики, флаги безопасности и профили браузеров установщик не изменяет.

После сопряжения соединение запоминается: ключ хранится в SecretStorage VS Code и локальном хранилище браузерного расширения. При перезапуске окно VS Code запускает локальный мост на прежнем порту, браузер восстанавливает соединение через HMAC, не передавая сохранённый ключ в запросе. Компонент работает с вкладками ChatGPT в подключённом профиле браузера. Открывайте проекты и чаты как обычно — содержимое передаётся автоматически. Если VS Code закрыт, браузер ждёт его запуска. Вручную открывать popup для каждого чата не требуется.

Пароли, cookies, auth.json и API-ключи аккаунта не читаются. Сопряжение ограничено одноразовой локальной страницей со сроком 5 минут. Онлайн-снимки остаются только в памяти до закрытия окна VS Code. Команда **Отключить онлайн ChatGPT и очистить снимки** забывает сохранённое подключение и очищает историю. При смене аккаунта сначала отключитесь, затем создайте новое соединение. Другое окно VS Code не перехватывает занятый порт; используйте окно, где уже настроен мост.

После подключения доступен сбор проектов: компонент раскрывает доступные списки, прокручивает их и посещает ссылки проектов, предоставленные самим ChatGPT, в неактивной служебной вкладке. Повторить можно кнопкой **«Загрузить проекты и их чаты»** в VS Code или popup. Связь чата с проектом сохраняется по projectId. Если проектов нет, откройте раздел «Проекты» в ChatGPT и повторите сбор. Если вы переходите в служебную вкладку, сбор останавливается и не закрывает её.

Откройте выбранный онлайн-чат в VS Code, введите текст и нажмите **«Отправить в ChatGPT»**. Только явно введённый текст передаётся через локальный мост в обычную форму исходного чата подключённого профиля. При необходимости компонент откроет чат в неактивной вкладке. Существующий черновик, вложение или текущая генерация в браузере блокируют отправку. Онлайн-вложения и выбор модели из VS Code не реализованы — используйте исходный ChatGPT.

Успех подтверждает появление нового сообщения на странице; отдельная проверка серверного сохранения не выполняется. При неизвестном результате автоматического повтора нет: проверьте исходный чат и только затем подтвердите проверку кнопкой панели. Просроченная команда не нажимает отправку после пробуждения. Обновление снимков не стирает черновик VS Code.

**Полнота аккаунта не гарантируется:** доступны обнаруженные и загруженные страницы; скрытые проекты, виртуализированные сообщения и непрогруженные записи могут отсутствовать. Проход ограничен по времени, счётчики показывают только полученные записи. Сайт может менять разметку. Архивирование и удаление онлайн-чатов, создание проектов ChatGPT и онлайн-вложения не добавлены. Индикатор текущей страницы не является глобальным статусом всех чатов аккаунта.

## Исправление старых проектов Codex

Старые записи с `source=vscode` и пустым `originator`, подтверждённые пользователем как история Codex, снова относятся к Codex. Явные метки ChatGPT/Work и ручное назначение имеют приоритет. На присланной структуре 224 записей: **219 Codex и 5 локальных Work**, вместо ошибочно скрытых 79 старых записей. Незнакомый явно записанный клиент остаётся неопределённым; по имени папки приложение не угадывается. Чаты и их содержимое не перемещаются и не удаляются.

## Проекты и разделы

- Откройте **Проекты Codex** на левой панели. Верхняя строка **Codex ▾** переключает **Codex**, **Архив Codex**, **ChatGPT** и **Источник не определён**. Архивные чаты Codex показаны отдельно по исходным проектам. Для ChatGPT видны статус соединения, ход сбора и объём обнаруженных записей.
- Раздел определяется по метаданным источника и originator. Например, `custom: chatgpt`, `atlas`, `codex_chatgpt_desktop` относятся к ChatGPT. Название модели и папка `new-chat` не определяют приложение.
- Неопределённые записи не смешиваются с двумя основными разделами. Правой кнопкой по чату → **Выбрать раздел для чата** можно задать его вручную или вернуть автоматическое определение.
- Это доступная локальная история выбранного хранилища. Полная облачная история ChatGPT этим расширением не загружается.
- При поддержке сервера читается весь постраничный каталог **project/list**: настоящие ID, названия, корни и пустые проекты. Для старых данных остаётся адаптер известных полей `.codex-global-state.json` и сопоставление по рабочим папкам.
- Отдельные рабочие папки с автоматическими именами `new-chat-*` показаны плоским списком **Отдельные чаты**, без множества одинаковых вложенных папок. Канонический projectId имеет приоритет над временным cwd.

**Создание проекта:** значок новой папки в заголовке панели или команда **Codex Projects: Создать новый проект…** → введите название → выберите родительскую папку. Будет создана новая папка и настоящая запись через `project/create` с ключом идемпотентности. Существующая папка не перезаписывается. Затем правой кнопкой по проекту → **Новый чат в проекте**; `thread/start` получает его projectId и выбранный cwd. При неопределённом результате создания папка сохраняется, предлагается обновить список, а сведения для диагностики сохраняются без токенов.

**Файлы:** значок папки справа от проекта открывает дерево в правой области того же окна. Папки раскрываются по запросу. Файл открывается в обычном редакторе слева от дерева, двойной щелчок закрепляет вкладку. Повторный выбор значка переключает проект в той же панели. Есть обновление, отслеживание создания/удаления и управление стрелками клавиатуры. Ссылки за пределы корня и циклы не раскрываются. Это правая область редактора с изменяемой шириной; положение штатных боковых панелей не меняется.

## Категории внутри проекта

Правой кнопкой по проекту → **Создать категорию внутри проекта…**. Например: «Машины», «UI», «Трассы». Они показываются вложенными папками именно этого проекта. Правой кнопкой по чату → **Переместить в категорию…**; доступны существующие категории, новая категория и «Без категории». Можно также перетаскивать чаты между категориями внутри одного проекта.

Правой кнопкой по категории можно переименовать её, создать в ней новый чат или удалить категорию. Удаление категории оставляет все её чаты в проекте. Архивные/скрытые назначения сохраняются. Ручной порядок действует в каждом таком списке; новый чат первым появляется в выбранной категории. Обычный новый чат без категории показывается наверху проекта среди чатов без категории.

Категории, принадлежность и порядок сохраняются в этом профиле VS Code и изолированы между проектами и разделами. Глобальный список разделов приложения Codex не изменяется.

## Доступ всего проекта

Режим внизу чата — **настройка всего проекта**. Изменение в одной вкладке синхронизируется с остальными открытыми чатами этого проекта. Модель и глубина остаются настройками отдельного чата. Режим можно выбрать также правой кнопкой по проекту → **Доступ всех чатов проекта…**.

У каждого проекта свой сохранённый режим; новые чаты получают его автоматически. Для канонического projectId рабочие деревья используют одну настройку. Другие проекты и хранилища имеют отдельные настройки. После перехода с версии 0.3 выберите нужный режим проекта: старые отдельные полные права чата не повышают автоматически права всех остальных чатов.

Изменение действует **со следующего сообщения**. Выполняющаяся задача сохраняет права, с которыми началась. Режим выбирает хост расширения из настройки проекта при отправке; устаревшее значение в отдельной вкладке не заменяет сохранённые права проекта.

## Управление чатами

Правой кнопкой по чату доступны:

- **Архивировать / Восстановить из архива** через настоящие `thread/archive` / `thread/unarchive`. Работающий чат сначала нужно остановить. В переключателе разделов выберите **Архив Codex** или нажмите значок архива в заголовке; там показаны только архивные чаты по исходным проектам. Для дальнейшей отправки сначала восстановите чат.
- **Удалить архивный чат навсегда…** доступно для архивного чата Codex. Модальное подтверждение показывает его название: история и связанные дочерние чаты будут удалены без восстановления, файлы проекта сохранятся. Работающий чат удалить нельзя; источник `localFiles` доступен только для чтения. Перед `thread/delete` серверный архив и состояние проверяются повторно. Отмена или ошибка API не запускает ручного удаления истории. После успеха закрывается вкладка и удаляются только принадлежащие этому чату копии вставленных вложений. Архив и удаление ChatGPT здесь не реализованы.
- **Закрепить / Открепить**. Закрепление отмечает чат и поднимает его наверх текущего списка. Метки сохраняются локально в расширении.
- **Переместить выше / ниже**, а также перетаскивание внутри проекта. Порядок сохраняется после перезапуска. Каждый новый чат появляется первым; сообщения в старом чате не меняют ручной порядок. Скрытие и повторный показ архива сохраняют прежнее место чатов. Закреплённые чаты также можно расположить вручную; новые появляются перед сохранённым порядком.

Крутилка показывается у активного чата, его категории, проекта и родительской группы, включая свёрнутое дерево; после прекращения активности родительский индикатор сбрасывается. Для онлайн-групп используется активность обнаруженных страниц. События `thread/status/changed`/`turn/*` обрабатываются сразу; ожидание разрешения и ответа отмечается отдельно. Для работы в приложении Codex или другом процессе дополнительно читаются приращения журналов сессий примерно раз в 2 секунды — без открытия и возобновления этих чатов. Состояние `notLoaded` отдельного сервера не объявляет чужую задачу завершённой. Начало/конец/прерывание хода отслеживаются по событиям журнала, а не просто по дате файла. Если незавершённый журнал не обновлялся более 2 минут, показывается **Статус не подтверждён**, без ложной вечной крутилки. Поэтому долгие тихие команды и клиенты без доступных журналов могут требовать подтверждения статуса.

Поиск охватывает все загруженные чаты выбранного раздела, а не только последние 50. Порядок и закрепления сохраняются в этом профиле VS Code; синхронизация этих настроек с интерфейсом приложения Codex не реализована.

## Общение в центре

Нажмите чат. Его история и поле ввода откроются в центральной вкладке. Ответы открытым текстом, ваши сообщения компактными блоками справа. Снизу выбираются модель, допустимая глубина размышлений и режим доступа. Каталог моделей загружается у сервера, без зашитого списка. Наличие модели в каталоге не гарантирует права аккаунта на генерацию.

**Enter** ставит запрос в очередь; в простое очередь начинает его сразу. В простое **Ctrl+Enter** отправляет новый запрос; во время ответа **Ctrl+Enter / «Уточнить сейчас»** направляет текст и вложения текущему ходу через `turn/steer` с ожидаемым `expectedTurnId`. Поле и добавление вложений доступны. Ошибка или завершившийся ход не превращает уточнение в новый `turn/start` автоматически. **Shift+Enter** добавляет строку, **■** останавливает текущий ход. Удержание Enter не создаёт повторы. Fn+Enter повторяет Ctrl+Enter только при переданном DOM-модификаторе Fn; иначе это обычный Enter. Для клавиатуры со скрытым Fn используйте Ctrl+Enter.

**«В очередь»** добавляет самостоятельный следующий запрос. Видимая очередь вмещает до 10 запросов; элемент можно убрать. Запросы запускаются по одному после завершения предыдущего хода и подтверждённого освобождения writer, с актуальными правами проекта перед каждой отправкой. Stop, ошибка и разрыв связи приостанавливают очередь; продолжение — явно кнопкой **«Продолжить очередь»**. При неизвестном результате сначала проверьте историю и удалите неопределённый элемент — автоматического повтора нет. Очередь существует только в открытой панели и не сохраняется через её закрытие или перезапуск.

При прокрутке вверх над полем ввода есть кнопка **↓** — перейти к последнему сообщению. Потоковый ответ сохраняет позицию при чтении старой переписки; после нажатия ↓ снова включается следование за концом ответа. Продолжается исходная сессия по ID. Новый неотправленный черновик не стирается при обработке очереди.

Поле ввода по умолчанию компактное и не растёт от длинного текста: он прокручивается внутри. Кнопка **«Развернуть / Свернуть»** меняет размер поля, сохраняя текст, выделение и положение курсора. После успешной отправки поле возвращается к компактному виду.

После завершения ответа и при закрытии вкладки расширение запрашивает освобождение чата и ждёт `thread/closed`; новая отправка дожидается этого подтверждения. Нулевая задержка выгрузки задаётся только запущенному расширением App Server через аргумент CLI, пользовательский config не меняется. Работающий другой клиент не прерывается и его writer не отбирается. Если чат удерживается другим клиентом, выводится объяснение, текст и вложения сохраняются; продолжите в исходном клиенте или дождитесь освобождения.

Освобождение касается только собственного процесса расширения. Codex Desktop или другой клиент может удерживать writer и в простое; завершение ответа не гарантирует снятия чужой блокировки. Автоматического подключения к закрытому stdio-процессу Desktop, перехвата writer или скрытого fork чата нет. 0.7.1 исправляет клавиши, а этот межпроцессный случай остаётся ограничением.

### Продолжить исходный чат в Codex Desktop

При writer-конфликте нажмите **«Продолжить в Codex с черновиком»**. Откроется **тот же ID чата**, текст будет передан как черновик, без автоотправки. Если полный URI с кодированным prompt длиннее 1800 символов, по этому явному нажатию полный текст копируется в системный буфер и открывается тот же чат без query; вставьте его через Ctrl+V, проверьте и отправьте в приложении.

Вложения передаются в тексте как локальные пути/контекст, не как нативные карточки Desktop. Исходные черновик и вложения в VS Code сохраняются. При конфликте запроса очереди используйте его кнопку **«В Codex»**: передаётся именно сохранённый запрос, а не новый текст поля ввода. Элемент остаётся в очереди; **после отправки в Desktop удалите его вручную**, чтобы не повторить запрос позже.

Это recovery через владельца: чужой процесс не останавливается, lock не снимается, новый ID/fork не создаётся. Реальный Desktop с пользовательской историей при QA не открывался; URI/clipboard проверены Node-стабами, а появление кнопок и сохранение запросов — в настоящем изолированном VS Code с двумя нативными App Server и подставным Desktop opener.

Сообщения и действия выводятся в исходном порядке, включая старые JSONL. Последовательные действия свёрнуты в блок **Действия Codex · N** между соответствующими сообщениями. Раскрываются отдельно команда, правка файлов, поиск и результаты инструментов. Внутренние инструкции и скрытые рассуждения не показываются.

Разрешения на команды, изменения и вопросы отображаются в чате. По умолчанию выбран доступ в пределах проекта с подтверждениями. Полный доступ выбирается явно. Сложные формы подключённых сервисов пока не поддерживаются; их можно отклонить и продолжить в приложении.

Вверху **Обновить**, **В приложении**, **Изменения**, **Терминал**. Терминальный вариант использует `--no-daemon resume ID` для бинарных файлов с неполным локальным пакетом; требуется Codex с поддержкой этого флага.

## Просмотр изменений

Нажмите **Изменения** в заголовке чата или значок папки у проекта. В правом дереве есть раздел **Изменения проекта · Git** и метки изменённых файлов в основном дереве. Файлы организованы по папкам; видны добавления, изменения, удаления, переименования и конфликты. Нажатие открывает встроенное сравнение VS Code **HEAD ↔ рабочая версия**, включая staged и unstaged в их итоговом состоянии. Это все незакоммиченные изменения, включая пользовательские; авторство Codex для списка Git не заявляется. Отдельное сравнение индекса не реализовано. Требуется Git и локальный репозиторий; без Git показывается пояснение.

В действиях Codex **Изменение файлов** есть счётчики добавленных/удалённых строк и кнопка **Посмотреть изменения**. Она открывает полученный патч конкретного действия или накопленный патч ответа в отдельной вкладке с подсветкой diff. Используются только возвращённые сервером изменения, без восстановления выдуманной исходной версии. Старые сессии, где патч не сохранён, могут быть доступны только через Git.

## Вложения, скиллы и плагины

**+** открывает меню: файлы и документы, папка, код из редактора, плагины и скиллы с поиском. Каталог получен от `skills/list` и `plugin/list` для cwd чата. Выбор скилла отправляет структурированный `skill`, выбор установленного включённого плагина — `mention` с `plugin://…`. Случайные выдуманные пункты не добавляются. При отсутствии API или доступных пакетов это показывается в меню. Установка и авторизация плагинов выполняются средствами Codex.

В дереве каждого проекта есть ветка **Скиллы → В проекте / Общие доступные**. Она показывает полученные от Codex записи, включая выключенные с явной меткой. Нажатие открывает локальный SKILL.md для просмотра. Каталог Skills встроенного Copilot ведётся отдельно: доступность пакета в Codex не создаёт автоматически его копию в проекте для Copilot.

До **10 элементов на сообщение**, включая файлы, папки, скиллы и плагины. Выбор файла принимает **любое расширение**, до **50 МиБ на файл**. Поддерживаемые изображения до 10 МиБ идут как native image input; известные текстовые форматы до 256 КиБ включаются содержимым в контекст. Изображения 10–50 МиБ, крупный текст, бинарные и остальные форматы передаются локальным путём для доступных инструментов. Прикрепление не запускает файл, binary не декодируется как UTF-8. Если инструмента чтения формата нет, модель должна сообщить об этом. Код из редактора — выделение либо открытый файл; папка добавляет путь без автоматической отправки всего содержимого.

Скопируйте изображение или файл любого формата, поставьте фокус в поле локального сообщения Codex и нажмите **Ctrl+V**, в том числе во время ответа. Появятся карточки вложений; отправка, уточнение или добавление в очередь остаются отдельным действием. **Ctrl+C** копирует, обычная вставка текста сохраняется. За одну вставку суммарно до **50 МиБ**, с лимитом **10 элементов на сообщение** и **50 МиБ на файл**. Копии остаются в локальном хранилище для истории. Нативные форматы буфера ОС, которые не передают файлы в webview, могут не распознаваться; физическое Ctrl+V отдельно не проверено.

Нативно переданные изображения показаны миниатюрами; нажатие открывает просмотр **1:1 / Вписать**, **Esc** закрывает его. Остальные файлы представлены карточками и локальными ссылками; чтение зависит от инструментов. Поддерживаются ссылки на файлы в ответах и результаты генерации изображений, когда сервер вернул данные или доступный локальный путь.

Старые вложения показываются, если сохранились файл, данные изображения или доступный URL. Один облачный fileId не восстанавливает исходный файл: такая карточка явно помечается недоступной. Выполняемые URI (`command:`, `javascript:`) не открываются.

Серое предложение в пустом поле — подсказка по последнему ответу. **Tab** вставляет её для редактирования; отправка остаётся отдельным действием. Подсказки строятся по текстовым правилам, без отдельного скрытого запроса к модели. Голосовой ввод и полный механизм подсказок приложения Codex не реализованы.

## Диагностика и проверки

**⋯ → Показать диагностику**: хранилище, источники, числа чатов, каталог проектов, выбранный раздел, неопределённые источники и ошибки статусов. Тексты переписок, токены и auth.json не включаются. Пути и имена могут содержать личные сведения.

В 0.7.1 проходят **85 Node-тестов** во всех десяти *.test.cjs. `node scripts/verify.mjs` проверяет закреплённый baseline, JSON, точки входа и синтаксис 31 JS-файла. После нового клона сначала выполнить `python scripts/fetch-baseline.py`. Команда всех тестов из PowerShell: `node --test --test-reporter=dot (Get-ChildItem -LiteralPath scripts -Filter *.test.cjs).FullName`.

В настоящем изолированном VS Code 1.145.2 KeyboardEvent Ctrl+Enter передал UI_STEER_CURRENT, Enter дважды enqueue, три хода завершились и черновик сохранился. Удержание Enter и переданный Fn покрыты unit-тестами; физический Fn не проверялся.

Нативный App Server 0.164.0-alpha.11.1 с локальным synthetic SSE подтвердил уточнение в том же turn и два следующих queued turn: три completed, четыре обращения к провайдеру. Настоящий VS Code 1.145.2 с изолированным профилем проверил actual send/steer/queue, вставку 10 backup.awg через DataTransfer во время ответа и сохранение нового черновика при опустошении очереди. Также пройдены writer handoff, заголовки, PNG/TXT clipboard send, архив/удаление синтетического чата с сохранением другого чата и файлов проекта, кэш cold/warm и компактное поле. Отмена удаления и guards покрыты unit-тестами. Неизменённая браузерная часть проверена синтетическим DOM/HTTP с обеих сторон.

Настоящая модель, авторизованный ChatGPT, обычный пользовательский профиль, установщики, macOS, установка/сопряжение браузера и физическое Ctrl+V не проверялись. Настоящий Desktop с пользовательской историей не открывался; системный clipboard проверен стабами; ответы были статическими через HTTP/SSE на 127.0.0.1. Онлайн-вложения и архив/удаление ChatGPT не реализованы.

Исходные npm-команды тестирования и сборки не работают: их скрипты не вошли в поставку. Упаковка и границы проверки описаны в docs/RELEASE.md репозитория и в СНАЧАЛА ПРОЧИТАЙ.txt нового комплекта.

Расширение неофициальное, не связано с OpenAI. Современные проектные API экспериментальные и могут меняться между версиями. Используемые структуры сверены с локальной схемой Codex 0.167.0-alpha.4 и исходниками [OpenAI Codex](https://github.com/openai/codex).
