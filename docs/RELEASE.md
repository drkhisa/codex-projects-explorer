# Выпуск версий

Версия: **MAJOR.MINOR.PATCH**.

- **MAJOR** — большие несовместимые изменения; пока остаётся 0.
- **MINOR** — новые возможности, например категории, браузерное подключение или просмотр изменений.
- **PATCH** — исправления существующих функций, например группировки, порядка дерева или подключения.

Текущий выпуск **0.7.2** исправляет недоступные списки модели/effort, загрузку длинной истории и определение активности по длинному журналу. После загрузки каталога модель и глубина размышлений (effort) снова доступны для выбора. Во время ответа можно выбрать настройки следующего запроса очереди; это не меняет модель уже выполняющегося хода. Уточнение через Ctrl+Enter / turn/steer продолжает текущий ход без замены модели. Пока каталог пуст или запрос ожидает подтверждения приёма, оба списка недоступны.
В настоящем изолированном VS Code 1.145.2 подтверждены доступность обоих списков после загрузки и во время ответа, смена модели с gpt-6.1-sol на gpt-6-astra через событие change и обновление допустимых effort. UI/warm отчёты pass:true; очередь, clipboard, handoff, кэш и компактное поле также прошли.
Версии в `extension/package.json`, браузерном manifest, VSIX manifest и
`installers/Windows/installer.json` должны совпадать.

При изменении поведения всегда обновлять README. При каждом выпуске сверять
корневой `README.md` и `extension/readme.md`: текущую версию, возможности,
инструкции, фактически выполненные проверки и ограничения. Описание репозитория
GitHub (About) должно отражать актуальное назначение проекта. Историческую
поставку 0.5.2 описывать отдельно; видимость репозитория при обновлении About
не менять. Корневой README не входит в пакеты: его отдельное исправление
не требует повышения версии или пересборки уже готового выпуска.

## Длинная история и активность

История через современный App Server открывается страницей до 20 последних ходов в хронологическом порядке. «Ранние сообщения» заменяет текущую страницу предыдущей, «К последним сообщениям» возвращает к актуальной; черновик сохраняется. Переходы истории недоступны во время активного хода и отрисовки. Отрисовка уступает интерфейсу управление каждые 40 элементов, без пересчёта прокрутки после каждого исторического tool. Старый API thread/read и локальный JSONL-fallback по-прежнему загружают историю целиком: ускорение по страницам для них не гарантируется.

Когда lifecycle-событие начала хода ушло за последний 1 МиБ журнала, определение активности ищет последнее lifecycle-событие назад блоками по 256 КиБ с ограниченным буфером. Отдельные JSONL-записи крупнее 1 МиБ при таком поиске пропускаются; oversized event_msg или нечитаемое начало такой записи оставляет статус неподтверждённым, чтобы не восстановить уже завершённый ход как активный. Попытка обратного поиска кэшируется, неизменённый unknown-журнал не перечитывается целиком при каждом опросе. Повторные проверки читают дописанные байты; порог свежести остаётся 2 минуты. Статус notLoaded чужого App Server и status последнего сохранённого хода не доказывают простой другого клиента; долгий ход без свежих событий по-прежнему может получить «Статус не подтверждён».

Финальная QA 0.7.2: 92 Node-теста в одиннадцати файлах и настоящая изолированная VS Code 1.145.2. Проверены recent/older/latest страницы после 23 дополнительных синтетических ходов нативного App Server и сохранение черновика. При отрисовке 1000 tool-элементов измерено 6 чтений scrollHeight. Синтетический журнал с выводом 1,5 МБ и task_started за хвостом включил индикаторы закреплённого чата и проекта; task_complete снял их. Cold/warm отчёты pass:true. Реальная история Nitru и другие пользовательские переписки не использовались.

## Клавиши, handoff и сохраняющийся writer-конфликт

Enter всегда enqueue; в простое очередь запускается сразу. Ctrl+Enter — steer
при активном ходе, send в простое; Shift+Enter — новая строка. Repeat-события
удерживаемого Enter не отправляют повтор. Fn эквивалентен Ctrl только если DOM
getModifierState('Fn') возвращает true; физически скрытый Fn не определяется.
Без переданного модификатора сочетание выглядит как обычный Enter.

Writer НЕ исправлен. Независимые stdio-серверы не разделяют writer автоматически;
исследованный Codex Desktop не предоставляет Unix-socket listener для proxy.
Освобождение собственного процесса расширения не освобождает чужой writer,
который может оставаться и в простое. Для продолжения исходного чата требуется
освобождение владельцем. Перехват, скрытый fork и автоматическое изменение
чужого config/чатов не выполняются. Это отдельное известное ограничение.

Handoff не снимает lock: при прямом конфликте предлагается «Продолжить в Codex
с черновиком», в очереди — «В Codex» для сохранённого item. Тот же ID передаётся
как codex://threads/id?prompt; установленный parser маршрутизирует его в
localConversation{prefillPrompt}, без autosend. При полном URI >1800 символов
явное нажатие копирует полный draft в clipboard и открывает тот же ID без query.
Вложения включены как локальные пути/контекст, без нативных карточек Desktop.
Черновик/вложения/элемент очереди не удаляются; после отправки в Desktop item
нужно убрать вручную, иначе позднее его можно отправить повторно.

Повторная QA handoff в 0.7.2: реальный изолированный VS Code 1.145.2 и два нативных App Server
воспроизвели foreign writer; обе настоящие кнопки передали тот же ID и нужный
сохранённый запрос в stub Desktop opener, сохранив исходный draft и очередь.
UI/warm отчёты pass:true. OS openExternal/clipboard проверены Node-стабами;
настоящий Desktop с пользовательской историей не открывался. Физический Fn
не проверен. Новые chat-handoff тесты обязательно входят в Git и общий прогон.

## Проверка и упаковка

Из корня проекта в PowerShell (каждую команду выполнять отдельно):

```powershell
rtk proxy powershell -NoProfile -Command '. .\scripts\Enter-Project.ps1; rtk proxy python scripts/fetch-baseline.py'
rtk proxy powershell -NoProfile -Command '. .\scripts\Enter-Project.ps1; rtk proxy node scripts/verify.mjs'
rtk proxy powershell -NoProfile -Command '. .\scripts\Enter-Project.ps1; rtk proxy node --test --test-reporter=dot (Get-ChildItem -LiteralPath scripts -Filter *.test.cjs).FullName'
rtk proxy powershell -NoProfile -Command '. .\scripts\Enter-Project.ps1; rtk proxy python scripts/build-release.py'
```

Нужны уже установленные Node.js и Python 3. Новые зависимости не устанавливаются.
После нового клона сначала загрузить исходную поставку командой fetch-baseline
выше. В `packaging/baseline.json` закреплены version/filename/размер/SHA-256/URL
оригинального ZIP из Release v0.5.2. Загрузчик проверяет pin до записи финального
файла и сохраняет его только в локальной, исключённой из Git папке `archives/`.
Существующий ZIP не перезаписывается; отсутствующий SHA256SUMS создаётся из pin.
При уже имеющемся правильном ZIP повторная загрузка не требуется. Verify и
сборщик также сверяются с отслеживаемым pin и сообщают команду при отсутствии
baseline. Без локального ZIP для первого bootstrap нужен доступ к Releases.

Сборщик создаёт `builds/<версия>/`: общий ZIP по структуре исходного выпуска,
отдельные VSIX и ZIP браузерного компонента, `SHA256SUMS`. Существующую папку
выпуска не перезаписывает. Упаковка использует только явный список файлов расширения
и установщиков; рабочая папка целиком в архив не попадает.

`installer.json` в репозитории — шаблон: пустое поле `sha256` заполняется
контрольной суммой нового VSIX внутри выпуска. Сборщик сверяет версии, перечень
файлов с исходным архивом, содержимое вложенных ZIP и VSIX, CRC и хеш установщика.
Время записей фиксировано, поэтому одинаковые исходники дают одинаковые архивы.
Сценарий Mac получает разрешение на исполнение внутри ZIP.

Архив `archives/Codex-Projects-All-0.5.2.zip` и его `SHA256SUMS` неизменяемы.
Они хранятся локально и как assets Release v0.5.2, а не в текущем Git tree.
Их удаление из индекса не удаляет рабочие копии и не переписывает историю.
`docs/original/` и история изменений описывают прошлую поставку, а не результаты
проверки новой версии. Исходные `npm test`, `npm run package` и
`npm run build:installer` не восстановлены; использовать команды выше.

## Публикация на GitHub

Выпуск завершён после доставки готовых пакетов через GitHub Releases и проверки
скачивания, а не только после commit/push исходников. Папки `builds/`, `.local/`
и `reports/` остаются исключёнными из Git.

1. Завершить проверки, собрать новый выпуск и проверить локальный `SHA256SUMS`.
2. Проверить diff, сделать commit и обычный push. Зафиксировать исходный коммит
   версии; незавершённые изменения других чатов не добавлять в коммит.
3. Запустить публикацию из корня проекта, указав версию и её исходный коммит:

```powershell
rtk proxy powershell -NoProfile -Command '. .\scripts\Enter-Project.ps1; rtk proxy python scripts/publish-release.test.py'
rtk proxy powershell -NoProfile -Command '. .\scripts\Enter-Project.ps1; $releaseCommit = (rtk proxy git rev-parse HEAD).Trim(); rtk proxy python scripts/publish-release.py 0.7.2 $releaseCommit --latest'
```

Скрипт использует стандартную библиотеку Python и существующий Git credential
helper без интерактивного входа. Авторизация и скачанные пакеты остаются только
в памяти; секреты не выводятся, не записываются и не передаются по редиректам.
Скрипт не пересобирает и не изменяет локальные пакеты. Он сверяет их SHA-256,
версии, вложенные VSIX/ZIP и содержимое VSIX с указанным коммитом, который должен
уже находиться в опубликованной ветке main. Различия окончаний строк Git/Windows
учитываются при сравнении текстовых исходников.

Для новой версии создаётся черновик Release с тегом `v<версия>` на исходном
коммите. Загружаются **все четыре файла**: All ZIP, Browser ZIP, VSIX и SHA256SUMS.
После сверки серверных размеров и digest черновик публикуется; каждый файл затем
скачивается по настоящему публичному URL и проверяется по размеру и SHA-256.
`--latest` назначает проверенный выпуск последним. При повторном запуске тег
должен указывать на тот же коммит, а существующие assets — совпадать по хешам.
Несовпадение останавливает публикацию без удаления или перезаписи файлов.

Историческая поставка v0.5.2 содержит два assets — оригинальный ZIP и SHA256SUMS.
Для её повторной сверки/доставки предусмотрен `--baseline`, без смены Latest:

```powershell
rtk proxy powershell -NoProfile -Command '. .\scripts\Enter-Project.ps1; rtk proxy python scripts/publish-release.py 0.5.2 6f908b0 --baseline'
rtk proxy powershell -NoProfile -Command '. .\scripts\Enter-Project.ps1; rtk proxy python scripts/fetch-baseline.test.py'
```

После публикации добавить настоящие ссылки Release и пакетов в README,
проверить latest и состав assets через API. Существующие архивы и исходные
коммиты старых версий не переписывать.

## Проверки 0.7.2 и ограничения

Пройдены 92 Node-теста во всех одиннадцати *.test.cjs. Общая проверка подтверждает
pin baseline, JSON, точки входа и синтаксис 31 JS-файла. Отдельно проходят
5 Python-тестов fetch-baseline и 3 теста публикации. Проверки упаковки сверяют
содержимое/CRC ZIP/VSIX, версии, хеш установщика, права Mac-сценария,
воспроизводимость и отказ перезаписывать готовый выпуск. После загрузки все
четыре assets скачиваются и сверяются по размеру/SHA-256; тег должен указывать
на source commit, Latest — на 0.7.2. Прежние пакеты и baseline неизменяемы.

В настоящем изолированном VS Code 1.145.2 KeyboardEvent Ctrl+Enter передал
UI_STEER_CURRENT, обычный Enter дважды enqueue (в том числе с 10 .awg), три
хода завершились и новый черновик сохранился. UI/warm отчёты pass:true. Два
новых unit-теста покрывают Enter/Ctrl+Enter/переданный Fn, idle send, Shift, IME
и удерживаемый repeat. Физический Fn не проверялся.

Нативный Codex App Server 0.164.0-alpha.11.1 с изолированными home/cwd и
статическим synthetic SSE только с 127.0.0.1 подтвердил turn/steer с expectedTurnId
в том же ходе и два следующих turn/start из очереди: три completed turns,
четыре provider requests, очередь пустая. Уточнение не имеет fallback на новый
turn/start. Перед отправкой каждого queued запроса заново берутся права проекта.

В настоящем VS Code 1.145.2 через extensionDevelopmentPath/extensionTestsPath
с изолированными профилем/расширениями/workspace/temp/crash/Codex home внутри
J:\ChatGPT\VS Code PlugIn\.local проверены реальные кнопки send/steer/queue,
вставка 10 backup.awg в DataTransfer во время работающего хода и два queued
запроса. Неотправленный черновик PRESERVE_WHILE_QUEUE_DRAINS сохранился,
очередь завершилась. Также проходят writer handoff второму настоящему процессу,
заголовки, PNG/TXT clipboard send, архивирование/удаление синтетического чата
с сохранением другого чата и файлов проекта, кэш cold/warm до ответа сервера,
компактное поле 76 px и ручное разворачивание с сохранением курсора.
Native/UI/warm отчёты pass:true. Все harness/fixtures/отчёты остаются в .local,
не входят в Git и release assets. Пользовательская история не использовалась.

Ограничения очереди: до 10 запросов, только пока панель открыта, без переноса
через закрытие или перезапуск. Stop/ошибка/разрыв связи ставят её на паузу;
продолжение выполняется явно. Неизвестный исход блокирует replay до проверки
истории и удаления неопределённого элемента. Автоматического повтора нет.

Файлы: любые расширения до 50 МиБ/файл; paste суммарно до 50 МиБ; 10 вложений
включая папки/скиллы. Нативный image input — поддерживаемые изображения до
10 МиБ, текст в контексте — известные форматы до 256 КиБ. Более крупные
изображения/текст и бинарные файлы передаются путём для инструментов, без
автозапуска и UTF-8-декодирования binary. Наличие инструмента не гарантируется.

Браузерный протокол/поведение не менялись после 0.6.0: проекты и текстовая
отправка покрыты прежними синтетическими DOM/HTTP-проверками с обеих сторон,
включая loopback/Host/Origin/bearer/HMAC/лимиты и неизвестный исход. Полный
архив аккаунта, онлайн-вложения, архив/удаление ChatGPT не реализованы.
Живой ChatGPT, настоящая модель/аккаунт, обычный пользовательский профиль,
физическое системное Ctrl+V, macOS, установщики и установка/сопряжение браузера
не проверялись; вызов системного буфера проверялся стабами; реальный handoff длинного текста меняет clipboard только по явному нажатию.

Перед выпуском актуализировать packaging/СНАЧАЛА ПРОЧИТАЙ.txt и оба README.
После VSIX выполнить Developer: Reload Window. Компонент в комплекте — 0.7.2,
совместимый с компонентом 0.6.0; при переходе с 0.5.x обновить его и вкладки ChatGPT.
Коммит/push и публикация четырёх проверенных assets выполняются по поручению
пользователя. archives/, builds/, .local/ и reports/ остаются вне Git.
