# Выпуск версий

Версия: **MAJOR.MINOR.PATCH**.

- **MAJOR** — большие несовместимые изменения; пока остаётся 0.
- **MINOR** — новые возможности, например категории, браузерное подключение или просмотр изменений.
- **PATCH** — исправления существующих функций, например группировки, порядка дерева или подключения.

Исправление жизненного цикла чата после 0.5.2 выпускается как **0.5.3**.
Версии в `extension/package.json`, браузерном manifest, VSIX manifest и
`installers/Windows/installer.json` должны совпадать.

При изменении поведения всегда обновлять README. При каждом выпуске сверять
корневой `README.md` и `extension/readme.md`: текущую версию, возможности,
инструкции, фактически выполненные проверки и ограничения. Описание репозитория
GitHub (About) должно отражать актуальное назначение проекта. Историческую
поставку 0.5.2 описывать отдельно; видимость репозитория при обновлении About
не менять. Корневой README не входит в пакеты: его отдельное исправление
не требует повышения версии или пересборки уже готового выпуска.

## Проверка и упаковка

Из корня проекта в PowerShell (каждую команду выполнять отдельно):

```powershell
rtk proxy powershell -NoProfile -Command '. .\scripts\Enter-Project.ps1; rtk proxy node scripts/verify.mjs'
rtk proxy powershell -NoProfile -Command '. .\scripts\Enter-Project.ps1; rtk proxy node --test scripts/chat-lifecycle.test.cjs'
rtk proxy powershell -NoProfile -Command '. .\scripts\Enter-Project.ps1; rtk proxy python scripts/build-release.py'
```

Нужны уже установленные Node.js и Python 3. Новые зависимости не устанавливаются.
Сборщик создаёт `builds/<версия>/`: общий ZIP по структуре исходного выпуска,
отдельные VSIX и ZIP браузерного компонента, `SHA256SUMS`. Существующую папку
выпуска не перезаписывает. Упаковка использует только явный список файлов расширения
и установщиков; рабочая папка целиком в архив не попадает.

`installer.json` в репозитории — шаблон: пустое поле `sha256` заполняется
контрольной суммой нового VSIX внутри выпуска. Сборщик сверяет версии, перечень
файлов с исходным архивом, содержимое вложенных ZIP и VSIX, CRC и хеш установщика.
Время записей фиксировано, поэтому одинаковые исходники дают одинаковые архивы.
Сценарий Mac получает разрешение на исполнение внутри ZIP.

Архив `archives/Codex-Projects-All-0.5.2.zip` и его `SHA256SUMS` неизменяемы.
`docs/original/` и история изменений описывают прошлую поставку, а не результаты
проверки новой версии. Исходные `npm test`, `npm run package` и
`npm run build:installer` не восстановлены; использовать команды выше.

## Границы проверки

Структура, синтаксис, синтетические регрессионные тесты и проверки упаковки
не заменяют запуск в VS Code Extension Host, настоящий Codex App Server,
Windows GUI, Mac или браузер. Установщики и сопряжение не запускаются при сборке.
Полная онлайн-история и отправка из VS Code остаются нереализованными.

Перед выпуском записать фактически выполненные проверки и ограничения в
`packaging/СНАЧАЛА ПРОЧИТАЙ.txt`; не переносить старые утверждения о тестах.
Коммит и обычный push выполняются только по поручению пользователя.
`builds/`, `.local/` и `reports/` в Git не добавлять.
