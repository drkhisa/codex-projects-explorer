# Выпуск версий

Версия: **MAJOR.MINOR.PATCH**.

- **MAJOR** — большие несовместимые изменения; пока остаётся 0.
- **MINOR** — новые возможности, например категории, браузерное подключение или просмотр изменений.
- **PATCH** — исправления существующих функций, например группировки, порядка дерева или подключения.

Текущий выпуск **0.5.5** исправляет получение названия нового чата после
первого принятого текстового сообщения и обновление метаданных при фоновом опросе.
Это PATCH после 0.5.4, которая синхронизировала только уже готовое имя/preview.
Версии в `extension/package.json`, браузерном manifest, VSIX manifest и
`installers/Windows/installer.json` должны совпадать.

При изменении поведения всегда обновлять README. При каждом выпуске сверять
корневой `README.md` и `extension/readme.md`: текущую версию, возможности,
инструкции, фактически выполненные проверки и ограничения. Описание репозитория
GitHub (About) должно отражать актуальное назначение проекта. Историческую
поставку 0.5.2 описывать отдельно; видимость репозитория при обновлении About
не менять. Корневой README не входит в пакеты: его отдельное исправление
не требует повышения версии или пересборки уже готового выпуска.

## Проверка и упаковка

Из корня проекта в PowerShell (каждую команду выполнять отдельно):

```powershell
rtk proxy powershell -NoProfile -Command '. .\scripts\Enter-Project.ps1; rtk proxy python scripts/fetch-baseline.py'
rtk proxy powershell -NoProfile -Command '. .\scripts\Enter-Project.ps1; rtk proxy node scripts/verify.mjs'
rtk proxy powershell -NoProfile -Command '. .\scripts\Enter-Project.ps1; rtk proxy node --test scripts/chat-lifecycle.test.cjs scripts/chat-title.test.cjs'
rtk proxy powershell -NoProfile -Command '. .\scripts\Enter-Project.ps1; rtk proxy python scripts/build-release.py'
```

Нужны уже установленные Node.js и Python 3. Новые зависимости не устанавливаются.
После нового клона сначала загрузить исходную поставку командой fetch-baseline
выше. В `packaging/baseline.json` закреплены version/filename/размер/SHA-256/URL
оригинального ZIP из Release v0.5.2. Загрузчик проверяет pin до записи финального
файла и сохраняет его только в локальной, исключённой из Git папке `archives/`.
Существующий ZIP не перезаписывается; отсутствующий SHA256SUMS создаётся из pin.
При уже имеющемся правильном ZIP повторная загрузка не требуется. Verify и
сборщик также сверяются с отслеживаемым pin и сообщают команду при отсутствии
baseline. Без локального ZIP для первого bootstrap нужен доступ к Releases.

Сборщик создаёт `builds/<версия>/`: общий ZIP по структуре исходного выпуска,
отдельные VSIX и ZIP браузерного компонента, `SHA256SUMS`. Существующую папку
выпуска не перезаписывает. Упаковка использует только явный список файлов расширения
и установщиков; рабочая папка целиком в архив не попадает.

`installer.json` в репозитории — шаблон: пустое поле `sha256` заполняется
контрольной суммой нового VSIX внутри выпуска. Сборщик сверяет версии, перечень
файлов с исходным архивом, содержимое вложенных ZIP и VSIX, CRC и хеш установщика.
Время записей фиксировано, поэтому одинаковые исходники дают одинаковые архивы.
Сценарий Mac получает разрешение на исполнение внутри ZIP.

Архив `archives/Codex-Projects-All-0.5.2.zip` и его `SHA256SUMS` неизменяемы.
Они хранятся локально и как assets Release v0.5.2, а не в текущем Git tree.
Их удаление из индекса не удаляет рабочие копии и не переписывает историю.
`docs/original/` и история изменений описывают прошлую поставку, а не результаты
проверки новой версии. Исходные `npm test`, `npm run package` и
`npm run build:installer` не восстановлены; использовать команды выше.

## Публикация на GitHub

Выпуск завершён после доставки готовых пакетов через GitHub Releases и проверки
скачивания, а не только после commit/push исходников. Папки `builds/`, `.local/`
и `reports/` остаются исключёнными из Git.

1. Завершить проверки, собрать новый выпуск и проверить локальный `SHA256SUMS`.
2. Проверить diff, сделать commit и обычный push. Зафиксировать исходный коммит
   версии; незавершённые изменения других чатов не добавлять в коммит.
3. Запустить публикацию из корня проекта, указав версию и её исходный коммит:

```powershell
rtk proxy powershell -NoProfile -Command '. .\scripts\Enter-Project.ps1; rtk proxy python scripts/publish-release.test.py'
rtk proxy powershell -NoProfile -Command '. .\scripts\Enter-Project.ps1; rtk proxy python scripts/publish-release.py 0.5.5 3b813c8 --latest'
```

Скрипт использует стандартную библиотеку Python и существующий Git credential
helper без интерактивного входа. Авторизация и скачанные пакеты остаются только
в памяти; секреты не выводятся, не записываются и не передаются по редиректам.
Скрипт не пересобирает и не изменяет локальные пакеты. Он сверяет их SHA-256,
версии, вложенные VSIX/ZIP и содержимое VSIX с указанным коммитом, который должен
уже находиться в опубликованной ветке main. Различия окончаний строк Git/Windows
учитываются при сравнении текстовых исходников.

Для новой версии создаётся черновик Release с тегом `v<версия>` на исходном
коммите. Загружаются **все четыре файла**: All ZIP, Browser ZIP, VSIX и SHA256SUMS.
После сверки серверных размеров и digest черновик публикуется; каждый файл затем
скачивается по настоящему публичному URL и проверяется по размеру и SHA-256.
`--latest` назначает проверенный выпуск последним. При повторном запуске тег
должен указывать на тот же коммит, а существующие assets — совпадать по хешам.
Несовпадение останавливает публикацию без удаления или перезаписи файлов.

Историческая поставка v0.5.2 содержит два assets — оригинальный ZIP и SHA256SUMS.
Для её повторной сверки/доставки предусмотрен `--baseline`, без смены Latest:

```powershell
rtk proxy powershell -NoProfile -Command '. .\scripts\Enter-Project.ps1; rtk proxy python scripts/publish-release.py 0.5.2 6f908b0 --baseline'
rtk proxy powershell -NoProfile -Command '. .\scripts\Enter-Project.ps1; rtk proxy python scripts/fetch-baseline.test.py'
```

После публикации добавить настоящие ссылки Release и пакетов в README,
проверить latest и состав assets через API. Существующие архивы и исходные
коммиты старых версий не переписывать.

## Границы проверки

Структура, синтаксис, синтетические регрессионные тесты и проверки упаковки
не заменяют запуск в VS Code Extension Host, настоящий Codex App Server,
Windows GUI, Mac или браузер. Установщики и сопряжение не запускаются при сборке.
Полная онлайн-история и отправка в онлайн ChatGPT из VS Code остаются нереализованными.

В 0.5.5 проходят 22 синтетических теста (9 на жизненный цикл, 13 на название)
и общая проверка, включая синтаксис 31 JS-файла. В чате разработки выполнена
протокольная интеграционная проверка на нативном App Server
Codex 0.164.0-alpha.11.1 с синтетическими home/cwd внутри `.local/tmp`.
Реальные Backend, ChatSession и createChatPanel с подставной панелью VS Code
выполнили `thread/start`, `model/list`, `thread/read`, `turn/start`,
`turn/completed` и фоновый `thread/list`. До отправки проверен отдельный
provider=synthetic, endpoint — локальный HTTP 127.0.0.1 со статическим SSE-ответом
без авторизации и внешних запросов. Ход завершился, обе подписи стали
«First synthetic message»; сервер вернул name:null и preview первого сообщения.
Дополнительно пройдена интеграционная UI-проверка в установленном VS Code 1.145.2.
Текущие исходники загружены через `--extensionDevelopmentPath`, QA-сценарий —
через `--extensionTestsPath`; профиль, расширения, рабочая папка, Codex home,
crash directory и временные файлы изолированы внутри `.local/tmp` на J:.
Реальные `controller.newChat`, WebviewPanel и renderer JS выполнили отправку
кнопкой HTML через нативный App Server. После завершения хода TreeItem.label,
WebviewPanel.title, document.title и h1 равнялись «First synthetic message».
После `thread/name/set` они стали «Updated synthetic title», черновик
«Synthetic unsent draft» сохранился. Отчёт pass:true, Code.exe завершился с кодом 0.
Для чтения DOM и нажатия кнопки использован QA-listener в существующем script/nonce;
продуктовые исходники не менялись. Harness и отчёты остаются только в `.local/`.
Настоящая модель, аккаунт, обычный пользовательский профиль, установщики,
macOS, браузер и сопряжение не проверялись; история пользователя не читалась.
Готовые выпуски `builds/0.5.3/` и `builds/0.5.4/` не изменяются.

Перед выпуском записать фактически выполненные проверки и ограничения в
`packaging/СНАЧАЛА ПРОЧИТАЙ.txt`; не переносить старые утверждения о тестах.
Коммит и обычный push выполняются только по поручению пользователя.
`builds/`, `.local/` и `reports/` в Git не добавлять.
