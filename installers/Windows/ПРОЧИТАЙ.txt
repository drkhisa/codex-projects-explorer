Codex Projects Explorer 0.7.2 — установка в Windows

ИСПРАВЛЕНИЕ 0.7.2
После загрузки каталога модель и глубина размышлений (effort) снова доступны для выбора. Во время ответа можно выбрать настройки следующего запроса очереди; это не меняет модель уже выполняющегося хода. Уточнение через Ctrl+Enter / turn/steer продолжает текущий ход без замены модели. Пока каталог пуст или запрос ожидает подтверждения приёма, оба списка недоступны.
В настоящем изолированном VS Code 1.145.2 подтверждены доступность обоих списков после загрузки и во время ответа, смена модели с gpt-6.1-sol на gpt-6-astra через событие change и обновление допустимых effort. UI/warm отчёты pass:true; очередь, clipboard, handoff, кэш и компактное поле также прошли.

1. Распакуйте архив целиком (правая кнопка → Извлечь всё).
2. Откройте распакованную папку и дважды нажмите Установить.cmd.
3. В появившемся окне нажмите Установить.
4. После завершения закройте и снова откройте VS Code.

Сначала откройте VS Code: установщик ищет путь по запущенному редактору.
Если редактор не найден автоматически, нажмите Выбрать… и укажите Code.exe или bin\code.cmd.
VS Code должен быть уже установлен. Это установщик расширения, а не редактора.
Права администратора, Node.js и ручной ввод команд не нужны.
Настройки безопасности PowerShell и исходники ваших проектов не изменяются.
Это установочный сценарий с графическим окном, не подписанный EXE.
Windows-окно установщика собрано здесь, но ещё не проверено запуском на вашей Windows.

На Mac используйте отдельный файл .vsix через VS Code → Extensions: Install from VSIX…

Для экспериментального онлайн ChatGPT: в VS Code нажмите Ctrl+Shift+P →
Codex Projects: Подключить онлайн ChatGPT. Следуйте инструкции в центральном окне.
Папка browser-bridge также включена в этот архив; прочитайте ПРОЧИТАЙ.txt в ней.
Браузерное расширение устанавливается отдельно вручную: это не полная синхронизация аккаунта.
После обновления VSIX выполните Developer: Reload Window. При переходе с 0.5.x для проектов
и текстовой отправки ChatGPT обновите браузерный компонент и вкладки ChatGPT.
Протокол совместим с 0.6.0, компонент в текущем комплекте — 0.7.2. Онлайн-вложения и полный архив аккаунта не добавлены.

СОХРАНЁННЫЕ ВОЗМОЖНОСТИ 0.7.1
Во время ответа Ctrl+Enter / «Уточнить сейчас» уточняет текущий ход, Enter / «В очередь»
ставит отдельный следующий запрос после завершения/release предыдущего.
Очередь до 10 запросов видна и поддерживает удаление элемента. Stop/ошибка/разрыв
ставят её на паузу; продолжение явно. Неизвестный исход сначала проверить
по истории и убрать неопределённый элемент — автоповтора нет. Очередь только
пока панель открыта, без сохранения между перезапусками.
Любые форматы до 50 МиБ/файл, до 10 вложений с папками/скиллами на сообщение;
paste суммарно до 50 МиБ. Изображения до 10 МиБ нативно, известный текст
до 256 КиБ в контексте; остальное — путь для инструментов без автозапуска.
Нативный App Server и изолированный VS Code проверили steer/queue и 10 .awg.
Настоящая модель/аккаунт, физическое Ctrl+V, macOS и установщики не проверялись.

КЛАВИШИ И ОГРАНИЧЕНИЕ (С 0.7.1)
Enter всегда ставит в очередь (в простое она запускается сразу), Ctrl+Enter
уточняет текущий ответ либо отправляет новый в простое, Shift+Enter — строка.
Fn+Enter эквивалентен Ctrl+Enter только при переданном Fn; скрытый аппаратный
Fn определить нельзя. Удержание Enter не создаёт повторные запросы.
Межпроцессный writer НЕ ИСПРАВЛЕН: другой клиент, включая Desktop, может
удерживать его даже в простое. Освобождается только собственный сервер
расширения; для исходного чата требуется освобождение владельцем. Скрытого
fork, перехвата writer или автоматического изменения пользовательских чатов нет.
Проверены 92 Node-теста и реальные KeyboardEvent в изолированном VS Code;
физический Fn, настоящий аккаунт, macOS и установщики не проверялись.

ПЕРЕДАЧА ЧЕРНОВИКА В ИСХОДНЫЙ ЧАТ DESKTOP
При writer-конфликте нажмите «Продолжить в Codex с черновиком»; для элемента
очереди — его «В Codex». Открывается тот же ID, без fork и автоотправки.
Если полный URI длиннее 1800 символов, по этому нажатию весь draft копируется
в системный буфер, чат открывается без query; вставьте Ctrl+V и отправьте.
Вложения идут текстом как локальные пути/контекст, не карточками Desktop.
Draft/вложения/очередь в VS Code сохраняются. ПОСЛЕ ОТПРАВКИ В DESKTOP УДАЛИТЕ
ЭЛЕМЕНТ ОЧЕРЕДИ ВРУЧНУЮ, чтобы не отправить его повторно. Чужой процесс не
останавливается, lock не снимается. Установленный parser поддерживает
prefillPrompt; реальный Desktop с пользовательской историей не открывался.
Настоящий VS Code с двумя native App Server и stub Desktop opener проверил
кнопки и сохранение данных; OS openExternal/clipboard проверены Node-стабами.

ДЛИННАЯ ИСТОРИЯ И АКТИВНОСТЬ
История через современный App Server открывается страницей до 20 последних ходов в хронологическом порядке. «Ранние сообщения» заменяет текущую страницу предыдущей, «К последним сообщениям» возвращает к актуальной; черновик сохраняется. Переходы истории недоступны во время активного хода и отрисовки. Отрисовка уступает интерфейсу управление каждые 40 элементов, без пересчёта прокрутки после каждого исторического tool. Старый API thread/read и локальный JSONL-fallback по-прежнему загружают историю целиком: ускорение по страницам для них не гарантируется.

Когда lifecycle-событие начала хода ушло за последний 1 МиБ журнала, определение активности ищет последнее lifecycle-событие назад блоками по 256 КиБ с ограниченным буфером. Отдельные JSONL-записи крупнее 1 МиБ при таком поиске пропускаются; oversized event_msg или нечитаемое начало такой записи оставляет статус неподтверждённым, чтобы не восстановить уже завершённый ход как активный. Попытка обратного поиска кэшируется, неизменённый unknown-журнал не перечитывается целиком при каждом опросе. Повторные проверки читают дописанные байты; порог свежести остаётся 2 минуты. Статус notLoaded чужого App Server и status последнего сохранённого хода не доказывают простой другого клиента; долгий ход без свежих событий по-прежнему может получить «Статус не подтверждён».

Финальная QA 0.7.2: 92 Node-теста в одиннадцати файлах и настоящая изолированная VS Code 1.145.2. Проверены recent/older/latest страницы после 23 дополнительных синтетических ходов нативного App Server и сохранение черновика. При отрисовке 1000 tool-элементов измерено 6 чтений scrollHeight. Синтетический журнал с выводом 1,5 МБ и task_started за хвостом включил индикаторы закреплённого чата и проекта; task_complete снял их. Cold/warm отчёты pass:true. Реальная история Nitru и другие пользовательские переписки не использовались.
