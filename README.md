# Codex Projects Explorer 0.7.0

Расширение VS Code для проектов и чатов Codex: история, центральный чат, уточнение текущего ответа и очередь, любые файлы, изменения Git и архив по проектам. Браузерный мост показывает доступные проекты ChatGPT и поддерживает явную текстовую отправку в исходный онлайн-чат.

GitHub: [drkhisa/codex-projects-explorer](https://github.com/drkhisa/codex-projects-explorer). Подробная установка и возможности: [extension/readme.md](extension/readme.md).

Новое в 0.7.0:

- Пока Codex отвечает, поле доступно: **Enter / «Уточнить сейчас»** передаёт уточнение через `turn/steer` с ожидаемым ID текущего хода. Ошибка не превращает его в новый запрос автоматически.
- **«В очередь»** добавляет следующий самостоятельный запрос. Видимая очередь вмещает до 10 запросов, позволяет убрать элемент и запускает их последовательно после завершения хода и освобождения writer. Права проекта заново проверяются перед каждым запросом. Stop, ошибка и разрыв связи приостанавливают очередь; продолжение — кнопкой **«Продолжить очередь»**.
- Неизвестный результат не переотправляется: проверьте историю и удалите неопределённый элемент перед продолжением. **Очередь живёт только в открытой панели** и не сохраняется между закрытием панели или перезапусками.
- Прикрепляются **любые форматы**, до **10 элементов на сообщение**, включая файлы, папки и скиллы. Каждый файл — до **50 МиБ**, одна вставка из буфера суммарно — до **50 МиБ**. Поддерживаемые изображения до 10 МиБ идут как native image input, известный текст до 256 КиБ — содержимым в контекст. Крупные изображения/текст и бинарные файлы передаются локальным путём для инструментов, без автоматического запуска и декодирования binary как UTF-8. Прикрепление пути не гарантирует наличие инструмента чтения формата.

Сохранены компактное поле с ручным разворачиванием, быстрый кэш метаданных, освобождение idle writer, индикаторы активности у родителей, онлайн-проекты и текстовая отправка ChatGPT, «Архив Codex» по проектам. Необратимое удаление архивного чата с подтверждением удаляет также дочерние истории, сохраняя файлы проекта. Полнота онлайн-аккаунта не гарантируется; онлайн-вложения, архив/удаление ChatGPT не реализованы.

Проверки: **76 Node-тестов**, **31 проверка синтаксиса JS**, 8 Python-тестов, проверки упаковки и SHA-256. Реальный нативный App Server 0.164.0-alpha.11.1 с локальным synthetic SSE подтвердил steer в тот же ход и два последующих queued turn: три завершённых хода, четыре обращения к провайдеру. В изолированном настоящем VS Code 1.145.2 проверены кнопки send/steer/queue, вставка 10 файлов backup.awg во время ответа, последовательная очередь и сохранение черновика, а также writer handoff, заголовки, clipboard, архив/удаление, кэш cold/warm и компактное поле.

Ответы были статическими на 127.0.0.1; настоящая модель, аккаунт ChatGPT, обычный профиль пользователя, физическое Ctrl+V, macOS, установщики и установка/сопряжение браузера не проверялись. Пользовательская история и системный буфер не использовались.

Пакеты хранятся в GitHub Releases и локально в `builds/0.7.0/`. Прежние готовые пакеты и исходный baseline не перезаписываются; бинарные поставки, кеши и QA-отчёты остаются вне Git.

## Разработка и проверки

Локальная папка проекта: `J:\ChatGPT\VS Code PlugIn`. Новые локальные файлы проекта должны оставаться внутри неё.

| Папка | Содержимое |
| --- | --- |
| `archives/` | Локальный baseline из Release v0.5.2; исключён из Git |
| `extension/` | Рабочие исходники VS Code и `browser-bridge/` |
| `installers/` | Установочные сценарии, инструкции и шаблон метаданных Windows/macOS |
| `packaging/` | Метаданные VSIX, закреплённый baseline.json и инструкция выпуска |
| `docs/` | Разбор исходника, роли агентов и оригинальные инструкции |
| `scripts/` | Настройка временных папок, проверки, тесты, упаковка и публикация Releases |
| `builds/` | Сборки по версиям и SHA-256; результаты исключены из Git |
| `reports/` | Локальные отчёты; результаты исключены из Git |
| `.local/` | Временные файлы и кеши; исключены из Git |

Из корня в PowerShell, каждую команду отдельно:

```powershell
rtk proxy powershell -NoProfile -Command '. .\scripts\Enter-Project.ps1; rtk proxy python scripts/fetch-baseline.py'
rtk proxy powershell -NoProfile -Command '. .\scripts\Enter-Project.ps1; rtk proxy node scripts/verify.mjs'
rtk proxy powershell -NoProfile -Command '. .\scripts\Enter-Project.ps1; rtk proxy node --test --test-reporter=dot (Get-ChildItem -LiteralPath scripts -Filter *.test.cjs).FullName'
```

Для последующей работы в уже открытом терминале выполнить `. .\scripts\Enter-Project.ps1`, затем запускать команды через `rtk`.

Загрузка baseline требует Python 3 и доступа к GitHub Releases при первом запуске; при наличии проверенного файла сеть не используется. ZIP скачивается в локальную `archives/`, размер и SHA-256 сверяются с отслеживаемым `packaging/baseline.json` до записи. Существующий исходник не перезаписывается. Проверки требуют установленный Node.js, не устанавливают пакеты и не запускают плагин. Регрессионные тесты используют синтетические данные внутри проекта. Исходные `npm test`, `npm run package` и `npm run build:installer` не работают: указанные в них файлы не вошли в поставку.

Правило **MAJOR.MINOR.PATCH**, команда упаковки на Python и границы проверки: [docs/RELEASE.md](docs/RELEASE.md). При изменении поведения всегда обновляется README; при каждом выпуске сверяются версия, возможности, инструкции, проверки и описание репозитория GitHub.
