## 0.7.2: выбор модели, длинная история и активность

PATCH исправляет недоступные списки модели и effort в готовом чате. После загрузки каталога модель и глубина размышлений (effort) снова доступны для выбора. Во время ответа можно выбрать настройки следующего запроса очереди; это не меняет модель уже выполняющегося хода. Уточнение через Ctrl+Enter / turn/steer продолжает текущий ход без замены модели. Пока каталог пуст или запрос ожидает подтверждения приёма, оба списка недоступны.

Узкий регрессионный тест проверяет загрузку каталога, смену модели и допустимого effort, отправку выбранных значений в очередь, временную блокировку и повторное включение списков. В настоящем изолированном VS Code 1.145.2 подтверждены доступность обоих списков после загрузки и во время ответа, смена модели с gpt-6.1-sol на gpt-6-astra через событие change и обновление допустимых effort. UI/warm отчёты pass:true; очередь, clipboard, handoff, кэш и компактное поле также прошли.

### Длинная история и активность

История через современный App Server открывается страницей до 20 последних ходов в хронологическом порядке. «Ранние сообщения» заменяет текущую страницу предыдущей, «К последним сообщениям» возвращает к актуальной; черновик сохраняется. Переходы истории недоступны во время активного хода и отрисовки. Отрисовка уступает интерфейсу управление каждые 40 элементов, без пересчёта прокрутки после каждого исторического tool. Старый API thread/read и локальный JSONL-fallback по-прежнему загружают историю целиком: ускорение по страницам для них не гарантируется.

Когда lifecycle-событие начала хода ушло за последний 1 МиБ журнала, определение активности ищет последнее lifecycle-событие назад блоками по 256 КиБ с ограниченным буфером. Отдельные JSONL-записи крупнее 1 МиБ при таком поиске пропускаются; oversized event_msg или нечитаемое начало такой записи оставляет статус неподтверждённым, чтобы не восстановить уже завершённый ход как активный. Попытка обратного поиска кэшируется, неизменённый unknown-журнал не перечитывается целиком при каждом опросе. Повторные проверки читают дописанные байты; порог свежести остаётся 2 минуты. Статус notLoaded чужого App Server и status последнего сохранённого хода не доказывают простой другого клиента; долгий ход без свежих событий по-прежнему может получить «Статус не подтверждён».

Финальная QA 0.7.2: 92 Node-теста в одиннадцати файлах и настоящая изолированная VS Code 1.145.2. Проверены recent/older/latest страницы после 23 дополнительных синтетических ходов нативного App Server и сохранение черновика. При отрисовке 1000 tool-элементов измерено 6 чтений scrollHeight. Синтетический журнал с выводом 1,5 МБ и task_started за хвостом включил индикаторы закреплённого чата и проекта; task_complete снял их. Cold/warm отчёты pass:true. Реальная история Nitru и другие пользовательские переписки не использовались.

Сохранены клавиши и передача черновика владельцу из 0.7.1.
В 0.7.2 **Enter всегда ставит запрос в очередь**, которая в простое запускает его сразу.
**Ctrl+Enter** уточняет текущий ответ, а в простое отправляет новый запрос.
**Shift+Enter** добавляет строку; удержание Enter не создаёт повторные запросы.
**Fn+Enter** повторяет Ctrl+Enter только если клавиатура/ОС передают Fn в DOM;
скрытый аппаратный Fn определить нельзя, без него сочетание выглядит как обычный Enter.

**Межпроцессная writer-блокировка сохраняется.** Освобождение idle writer относится
только к App Server, запущенному расширением. Другой клиент, включая Codex Desktop,
может продолжать держать writer даже после ответа. Этот PATCH не исправляет такой
конфликт, не отбирает чужой writer и не создаёт скрытую копию чата. Продолжайте
в исходном клиенте или дождитесь освобождения; черновик и вложения сохраняются.

### Продолжить исходный чат в Codex Desktop

При writer-конфликте нажмите **«Продолжить в Codex с черновиком»**. Откроется **тот же ID чата**, текст будет передан как черновик, без автоотправки. Если полный URI с кодированным prompt длиннее 1800 символов, по этому явному нажатию полный текст копируется в системный буфер и открывается тот же чат без query; вставьте его через Ctrl+V, проверьте и отправьте в приложении.

Вложения передаются в тексте как локальные пути/контекст, не как нативные карточки Desktop. Исходные черновик и вложения в VS Code сохраняются. При конфликте запроса очереди используйте его кнопку **«В Codex»**: передаётся именно сохранённый запрос, а не новый текст поля ввода. Элемент остаётся в очереди; **после отправки в Desktop удалите его вручную**, чтобы не повторить запрос позже.

Это recovery через владельца: чужой процесс не останавливается, lock не снимается, новый ID/fork не создаётся. Реальный Desktop с пользовательской историей при QA не открывался; URI/clipboard проверены Node-стабами, а появление кнопок и сохранение запросов — в настоящем изолированном VS Code с двумя нативными App Server и подставным Desktop opener.

Сохранённые возможности:

- Пока Codex отвечает, поле доступно: **«Уточнить сейчас»** передаёт уточнение через `turn/steer` с ожидаемым ID текущего хода. Ошибка не превращает его в новый запрос автоматически.
- **«В очередь»** добавляет следующий самостоятельный запрос. Видимая очередь вмещает до 10 запросов, позволяет убрать элемент и запускает их последовательно после завершения хода и освобождения writer. Права проекта заново проверяются перед каждым запросом. Stop, ошибка и разрыв связи приостанавливают очередь; продолжение — кнопкой **«Продолжить очередь»**.
- Неизвестный результат не переотправляется: проверьте историю и удалите неопределённый элемент перед продолжением. **Очередь живёт только в открытой панели** и не сохраняется между закрытием панели или перезапусками.
- Прикрепляются **любые форматы**, до **10 элементов на сообщение**, включая файлы, папки и скиллы. Каждый файл — до **50 МиБ**, одна вставка из буфера суммарно — до **50 МиБ**. Поддерживаемые изображения до 10 МиБ идут как native image input, известный текст до 256 КиБ — содержимым в контекст. Крупные изображения/текст и бинарные файлы передаются локальным путём для инструментов, без автоматического запуска и декодирования binary как UTF-8. Прикрепление пути не гарантирует наличие инструмента чтения формата.

Сохранены компактное поле с ручным разворачиванием, быстрый кэш метаданных, освобождение idle writer, индикаторы активности у родителей, онлайн-проекты и текстовая отправка ChatGPT, «Архив Codex» по проектам. Необратимое удаление архивного чата с подтверждением удаляет также дочерние истории, сохраняя файлы проекта. Полнота онлайн-аккаунта не гарантируется; онлайн-вложения, архив/удаление ChatGPT не реализованы.

В QA 0.7.1 в настоящем изолированном VS Code 1.145.2 проверены KeyboardEvent: Ctrl+Enter передал UI_STEER_CURRENT, Enter дважды поставил запрос в очередь, три хода завершились, новый черновик сохранился. Физический Fn не проверялся; переданный DOM-модификатор Fn покрыт unit-тестом.

Проверки: **92 Node-теста**, **31 проверка синтаксиса JS**, 8 Python-тестов, проверки упаковки и SHA-256. Реальный нативный App Server 0.164.0-alpha.11.1 с локальным synthetic SSE подтвердил steer в тот же ход и два последующих queued turn: три завершённых хода, четыре обращения к провайдеру. В изолированном настоящем VS Code 1.145.2 проверены кнопки send/steer/queue, вставка 10 файлов backup.awg во время ответа, последовательная очередь и сохранение черновика, а также writer handoff, заголовки, clipboard, архив/удаление, кэш cold/warm и компактное поле.

Ответы были статическими на 127.0.0.1; настоящая модель, аккаунт ChatGPT, обычный профиль пользователя, физическое Ctrl+V, macOS, установщики и установка/сопряжение браузера не проверялись. Пользовательская история не использовалась. Вызов системного clipboard покрыт стабами; при настоящем handoff длинного черновика он изменится только после явного нажатия.

Пакеты хранятся в GitHub Releases и локально в `builds/0.7.2/`. Прежние готовые пакеты и исходный baseline не перезаписываются; бинарные поставки, кеши и QA-отчёты остаются вне Git.

## Разработка и проверки

Локальная папка проекта: `J:\ChatGPT\VS Code PlugIn`. Новые локальные файлы проекта должны оставаться внутри неё.

| Папка | Содержимое |
| --- | --- |
| `archives/` | Локальный baseline из Release v0.5.2; исключён из Git |
| `extension/` | Рабочие исходники VS Code и `browser-bridge/` |
| `installers/` | Установочные сценарии, инструкции и шаблон метаданных Windows/macOS |
| `packaging/` | Метаданные VSIX, закреплённый baseline.json и инструкция выпуска |
| `docs/` | Разбор исходника, роли агентов и оригинальные инструкции |
| `scripts/` | Настройка временных папок, проверки, тесты, упаковка и публикация Releases |
| `builds/` | Сборки по версиям и SHA-256; результаты исключены из Git |
| `reports/` | Локальные отчёты; результаты исключены из Git |
| `.local/` | Временные файлы и кеши; исключены из Git |

Из корня в PowerShell, каждую команду отдельно:

```powershell
rtk proxy powershell -NoProfile -Command '. .\scripts\Enter-Project.ps1; rtk proxy python scripts/fetch-baseline.py'
rtk proxy powershell -NoProfile -Command '. .\scripts\Enter-Project.ps1; rtk proxy node scripts/verify.mjs'
rtk proxy powershell -NoProfile -Command '. .\scripts\Enter-Project.ps1; rtk proxy node --test --test-reporter=dot (Get-ChildItem -LiteralPath scripts -Filter *.test.cjs).FullName'
```

Для последующей работы в уже открытом терминале выполнить `. .\scripts\Enter-Project.ps1`, затем запускать команды через `rtk`.

Загрузка baseline требует Python 3 и доступа к GitHub Releases при первом запуске; при наличии проверенного файла сеть не используется. ZIP скачивается в локальную `archives/`, размер и SHA-256 сверяются с отслеживаемым `packaging/baseline.json` до записи. Существующий исходник не перезаписывается. Проверки требуют установленный Node.js, не устанавливают пакеты и не запускают плагин. Регрессионные тесты используют синтетические данные внутри проекта. Исходные `npm test`, `npm run package` и `npm run build:installer` не работают: указанные в них файлы не вошли в поставку.

Правило **MAJOR.MINOR.PATCH**, команда упаковки на Python и границы проверки: [docs/RELEASE.md](docs/RELEASE.md). При изменении поведения всегда обновляется README; при каждом выпуске сверяются версия, возможности, инструкции, проверки и описание репозитория GitHub.
